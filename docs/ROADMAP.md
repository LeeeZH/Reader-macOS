# Reader for macOS · 路线图

这份文件回答一个问题：**接下来做什么，以及明确不做什么。**
用户视角的功能说明见 [README](../README.md)，实现细节与踩坑记录见 [开发笔记](DEVELOPMENT.md)。

排期原则：**先把「读一本书」这件事补完整，再谈换格式和联网。**
所以顺序是「全文搜索 → 窗口置顶 → 排版能力补齐 → 快捷键自定义 → 发版 → EPUB →（大概率不做）在线书源」，
而不是按原版功能表从上往下抄。

工程约束（每个决策都受它约束）：

| 约束 | 后果 |
|---|---|
| 零第三方依赖 | 不做需要引入库的功能（例如现成的 ZIP / HTML 库） |
| 只出 arm64 | 不承诺 Intel 支持，除非有机器可以真机验证 |
| `.cache.dat` 与 Windows 版字段互通 | 不新增「必须写进存档才能工作」的核心状态；Mac 专属偏好一律走 `macos_*` 自定义键 |
| 位置一律是 `FormatText` 之后的 UTF-16 码元下标 | 任何新功能都必须用字符偏移，不能引入「页码 / 百分比」当坐标 |
| 完全离线 | 联网功能需要先改产品承诺，见 M8 |

## M1 全文搜索（已完成）

**目标**：`⌘F` 一次扫完整本书，列出每一处的章节与上下文；回车 / `⌘G` 往下、
`⇧⌘G` 往回；当前页高亮；关面板清高亮。

**关键决策**

- 匹配交给 `NSString.range(of:options:range:)`：返回值天然是 UTF-16 下标，
  和进度 / 书签 / 章节锚点是同一套坐标。自己折叠大小写会改变长度，
  下标就不是原文偏移了。
- 命中**非重叠**（`aaaa` 查 `aa` = 2 处），单次最多收 2000 处（`truncated` 提示）。
- **搜索不跳页**：结果只列出来（顺手选中离阅读位置最近的一处），跳转必须是用户的主动动作 ——
  双击结果行、回车、点「跳转」，或 `⌘G` / `⇧⌘G`。打字时结果每 250ms 换一批，
  自动跳页会一边打字一边把人甩走。
- **关闭 = 本次查找结束**：关掉面板会清空输入框、结果和高亮；下次 `⌘F` 是干净的一次查找，
  不会带着上次的词，也不会跳回上次的位置。
- 输入防抖 250ms + 后台队列 + generation 丢弃过期结果，长篇打字不卡。
- 高亮只画「当前页 + 平滑滚动的下一页」的交集，翻页 / 换字号后自动重算。
- `⌘F` 归查找，全屏改为 `⌃⌘F`（系统标准「进入全屏幕」）。

**验收**：`./verify.sh` 里的 `4.9/5 全文搜索自检` 全绿；单测含偏移、大小写、
非重叠、上限、环绕、片段裁剪、设置往返；自检覆盖「搜索不跳页 / 单击不跳 / 关闭清空输入框 /
重新打开是空白查找」；离屏渲染 `--render-find` 与 `--render-page … --find 之` 人工确认高亮。

**实测**（638 万码元长篇，单测里已断言）：缓存构建 0.7ms（**不能**退回
`String(decoding:)`，那是 617ms）、命中密集 32ms、全书零命中扫描 171ms，
全部在 300ms 预算内。

## M2 窗口置顶（已完成）

**目标**：勾上设置后，主窗口浮在其它应用的普通窗口 / **最大化窗口**之上；
点别的应用也不会被挡在后面，方便一边在别的软件里干活、一边看着书。

**做法（最小、稳定的一级）**

- `window.level = .floating`（关掉时回到 `.normal`），在 `applyWindowChrome()` 里统一应用。
- `window.hidesOnDeactivate = false`：失焦不隐藏。NSWindow 默认就是 false，
  显式写出来是防止以后为了「不抢焦点」把主窗口改成 `NSPanel` 时悄悄变成默认 true。
- **只置顶主窗口**：辅助窗口（设置 / 书架 / 书签 / 查找）保持普通 level，不跟着浮在
  别的应用上面。但 level 是系统级绝对排序，主窗口 floating 时辅助窗口会被书盖住，
  所以辅助窗口可见期间主窗口临时降回 normal，关掉后（主窗口重新成为 key）自动恢复。
- 开关联动（同一个 `keepOnTop` 设置，任一处切换其它处立刻同步）：
  **菜单「视图 → 窗口置顶」`⌃⌘T`**、**右上角菜单栏图标的菜单**、**设置 → 窗口 → 置顶**。
  托盘菜单打开时按 `menuNeedsUpdate` 重读状态，主菜单项由 `syncKeepOnTopMenuState()` 统一刷新。
- 存自定义键 `macos_always_on_top`（Windows 版忽略）。

**明确不做**

- 盖住别人的**原生全屏**（绿色按钮）：那是独立 Space，要 `.canJoinAllSpaces` +
  `.fullScreenAuxiliary` + 更高 level，属于系统没承诺的灰区。本需求只要「最大化不挡」，
  floating 就够，而且稳定。
- 「点窗口不抢焦点」：用户明确说焦点丢了没关系 —— 滚轮悬停在阅读器上照样能翻，
  鼠标事件是按窗口命中派发的，不需要窗口是 key。

**验收**：`--always-on-top-selftest` 全绿（默认 normal、开启后 floating、失焦不隐藏、
辅助窗口保持 normal 且主窗口临时降级、关掉辅助窗口后恢复、三处开关联动、写盘后重新加载仍生效）；
单测覆盖设置往返与 level 数值关系；人工：勾上后切到别的应用，
窗口仍在最上面。

## M3 章节标题独立字体 / 颜色（已完成）

**为什么**：`.cache.dat` 里 `use_same_font` / `font_title` / `font_color_title`
三个字段已经能读写，但渲染层只有一个字体 —— 从 Windows 版搬过来的用户会发现
「设置还在、效果没了」。

**做法**

1. `ReaderSettings` 增加 `useSameFont`（header `use_same_font`，原版默认 1）、
   `titleFontName` / `titlePointSize`（header `font_title` 的 LOGFONT，
   换算与正文字体相同）；`titleColorRef` 已有。
2. `ReadingView` 从单个 `metrics` 变成「正文 / 标题」两套 `TextMetrics`；
   `LineBox` 增加 `style`（`.body` / `.title`）；`layout(from:)` 里标题行用标题度量
   算宽度和行高；`drawLines` / `drawChar` 按行取字体与颜色。
3. 设置界面「显示」页加「章节标题」分节（checkbox + 字体 + 字号 + 颜色），
   复用现有 `syncFromSettings` 刷新套路。

**实现时的三个关键约束**（照原版语义，别"优化"掉）

- `use_same_font = 1` 时原版 `Page::SelectFont` **连标题颜色都不看**（整行走 dc 0），
  所以同字体模式下 `renderTitleColor` 直接返回正文颜色；只有关掉同字体，
  `font_color_title` 才生效。
- 同字体模式下 `titleMetrics` **故意留 nil**，标题行直接复用正文那套 `TextMetrics`。
  多建一套同样的度量虽然数值一样，但把「默认行为不变」变成了"数值恰好相等"，
  以后改 `TextMetrics` 就可能悄悄动到分页基准。
- 标题的「标题性」按**字符区间**判定，不是只看「行首正好是章首」：原版
  `is_title = IsChapter(start)`，而 `Book::IsChapter` 是区间测试
  `idx >= ch.index && idx < ch.index + title_len`（Book.cpp:260）。所以
  ① 折行后的续行仍是标题；② 一页如果从**长标题中间**开始（翻页、翻页重叠行、
  跳转到标题内偏移、平滑滚动的下一页），续页的续行也还是标题。
  写成「只在段落开头重新判断、初值 false」会让标题在换页处突然掉回正文字体。

**兼容性红线**：默认值仍是「同字体同色」，所以 `samples/golden-pages.tsv`
不该变；用户开启后每页行数可能变化，但进度 / 书签是字符偏移，不受影响。

**验收（已跑）**

- `./test.sh`：新增 `[26] 章节标题独立字体 / 颜色` 一节（字段 round-trip、默认行样式全 body、
  开启后标题行高 > 正文行高、切回同字体后分页完全恢复、折行续行仍是标题字体）。
- `./verify.sh`：新增 `4.12 分页 golden 比对`（`--dump-pages` 与 `samples/golden-pages.tsv`
  逐字节 diff），全绿；这一步以前只导出不比对，M3 之后任何排版改动都会被它拦住。
- 离屏渲染对比：`--render-page 书 0` 与 `--render-page 书 0 --title-font "Songti SC" --title-size 26`
  各一张（`verify.sh` 输出 `page-title-same.png` / `page-title-separate.png`）。

## M4 背景图片（已完成）

原版 `bg_image.enable / mode / file_name` 三个字段读写在 M0 就有了格式支持，
但 `ReaderSettings` 没映射、设置界面没入口、绘制层也没画 —— M4 把这三处补齐。

**做法**

1. `ReaderSettings` 增加 `bgImageEnabled` / `bgImageMode` / `bgImageFileName`，
   直接读写 `header.bg_image` 对象（不新增自定义键；对象里的未知子字段原样保留）。
2. 铺法拆成纯计算：`Sources/Layout/BackgroundImageLayout.swift` 按模式算出
   「瓦片矩形 + 是否镜像」，不碰绘制 API，所以可以单测。
   `mode` 语义照原版 `DisplaySet.cpp`：**0 = 拉伸、1 = 平铺、2 = 平铺翻转**
   （`TileFlip` 对应 GDI+ 的 `WrapModeTileFlipXY` —— 奇数行/列镜像成棋盘）。
3. `ReadingView` 画三层：纯色底 → 背景图 → 正文；窗口 `alpha < 255` 时
   两层一起淡，但**文字始终不透明**（既有原则）。
4. 设置 → 显示新增「背景图片」分节（启用 / 模式 / 选文件 / 清除）；
   文件不存在时静默回落纯色并在设置页标红提示，不弹窗、不崩。

**两个实现细节**（别"优化"掉）

- **整层缓存**：铺好的背景合成成一张和视图等大的位图再画。平滑滚动每帧都重绘，
  平铺模式逐片 `draw` 上千次会掉帧（原版也是先合成到窗口大小的位图）。
  缓存的 key = 路径 + 模式 + 视图尺寸 + backingScale。
- **片数上限 2000**：1×1 的图片铺满 1000×800 是 80 万片，会直接把主线程钉死。
  超限时把瓦片等比放大到上限以内（视觉上仍是铺满的花纹）。原版走 GDI+ 纹理 wrap，
  没有这个坑。
- **半透明窗口的淡出不能用 `ctx.setAlpha`**：`NSImage.draw` 走 AppKit 绘制路径，
  不吃 CGContext 的全局 alpha，图会整块不透明地盖上去（半透明窗口看起来完全不透明）。
  淡出要显式传 `fraction:`，同时把全局 alpha 复位，避免 alpha²。回归测试见 `[27] 27.8`。

**验收（已跑）**

- `./test.sh`：新增 `[27] 背景图片` 一节 46 项 —— 三字段 round-trip、未知子字段保留、
  三种铺法的瓦片数/尺寸/镜像棋盘、非法尺寸、1×1 图片的片数上限、
  加载成功 / 文件缺失回落 / 关掉后清标记、设置页置灰与缺失提示、半透明下背景图跟着淡。
- `./verify.sh`：新增 `4.13 背景图片` 步 —— 拉伸 / 平铺 / 平铺翻转各渲染一张
  （`page-bg-0/1/2.png`），并断言文件缺失时仍然出图（退出码 0）。
- 夹具：`samples/bg-tile.png`（48×48，四色象限 + 不对称字母 F + 角点，用来肉眼检查
  平铺原点与镜像方向）。

## M5 快捷键自定义（已完成）

**为什么**：菜单键位原来全是 `AppDelegate.buildMenu()` 里写死的 `keyEquivalent`，
用户只能用作者挑的那套。原版 Windows 有 `Keyset.cpp`（18 个键可改，还能禁用），
Mac 版不能反而更差。

**做法**

1. `Sources/Core/Shortcut.swift`：`KeyCombo`（修饰键 + 键）+ 存盘格式 + 显示格式 + 校验。
2. `Sources/Core/ShortcutAction.swift`：21 个可改功能的注册表（稳定 id / 标题 / 分组 /
   默认键位）。菜单和设置页都从这张表生成，**不再有第二处写死的快捷键**。
3. `ReaderSettings` 走自定义键 `macos_shortcuts`（只存覆盖项，空串 = 清掉绑定）。
   没有覆盖时整个键不写，老用户 / Windows 存档的文件里不会平白多一行。
4. `Sources/Views/ShortcutRecorderView.swift`：点一下就地录制（Esc 取消、Delete 清除），
   录制期间用**本地事件监听**截按键 —— 菜单的 key equivalent 在事件分发阶段就抢走了，
   只靠 `keyDown` 录不到 ⌘ 组合（还会真的把 app 退掉）。
5. 设置 → 快捷键：按菜单分组，每行「功能 · 当前键位 · 还原」；冲突时**窗口底部固定
   提示条**写明「哪个键被哪个功能占用，尚未保存」+ **交换 / 取消**；底部「全部还原默认」。
6. 菜单、状态栏、编辑模式提示、书签 / 查找 / 章节搜索 / 书架的空状态提示，
   全部改成实时取当前键位。显示分两种：**快捷键设置页用全称**（`command + F`，
   方便认键）；**其他界面用图标**（`⌘F`），和 macOS 菜单栏的习惯一致。

**默认键位的一处改动**：添加书签 `⌘M → ⌘D`。`⌘M` 是 macOS 的「最小化」，
原来两个菜单项都绑 `⌘M`，菜单栏顺序让书签赢、最小化实际上按不出来。
现在 `⌘M` 还给最小化，书签用浏览器 / 阅读器通用的 `⌘D`。

**明确不改的部分**：系统标准键（`⌘Q` 退出、`⌘H` 隐藏、`⌘W` 关闭窗口、`⌘M` 最小化）
不在可改列表里，避免用户把自己关不掉；全局热键 `⌃⌥H` 仍是「设置 → 窗口」里的开关。

**验收（已跑）**

- `./test.sh`：新增 `[28]` 43 项 —— 存盘往返、显示全称（无图标）、裸字母 / 保留键校验、
  注册表默认键位互不冲突、覆盖 / 清空 / 还原、`macos_shortcuts` 读写、Windows 存档回默认。
- `./verify.sh`：新增 `4.14 快捷键自检` —— 菜单键位跟随设置、录制、
  冲突时窗口底部固定提示条可见且写明对家、切页 / 关窗 / 取消后的状态恢复、交换、
  单个 / 全部还原、写盘重载、设置页文案实时；全绿。
- 离屏渲染 `--render-settings <png> 4` 检查排版（4 = 快捷键标签页）。

## M7 EPUB（押后）

**为什么押后**：不是不想做，是它需要一次结构性重构，而不是加一个解析器。

**前置条件**

1. 把 `TextBook` 抽成 `Book` 协议（`units` / `chapters` / `titleLength` / 书名 /
   路径），`ReadingView`、书架、`.cache.dat` 都面向协议。
2. 一个零依赖的 ZIP 读取方案。先做**原型**：用 `Process` 调系统自带的
   `ditto -x -k` 解到临时目录，读 `META-INF/container.xml` → OPF → spine。
   原型验证「值不值得」之后，再决定要不要用 libz 自己写 inflate。
3. 文本规范化要单独一套：不能复用 `FormatText` —— 那套规则是为 **Windows 存档
   偏移兼容** 服务的，硬套到 EPUB 上只会把排版弄坏。
4. 一个 spine 条目 = 一章（合并 HTMLBlock 文本）；图片 / 样式 / 注音先忽略，
   番外与目录页按章节规则处理。

**验收**：打开一本公开版权的 EPUB 能读到正文、章节表正确、进度可记忆；
不引入任何第三方依赖；`.cache.dat` 结构不变。

## M8 在线书源（暂不做，需要产品决策）

**技术成本**：URLSession + HTML 解析 + 一套 XPath 子集（原版 `bs.json` 是 XPath 规则）
+ 书源规则界面 + 章节下载与缓存。零依赖前提下这是典型的「大工程」。

**产品冲突**：README 现在明确写着「完全离线：不联网、不上传、不统计」。
一旦加入书源，这个承诺就不成立了，必须同时改：
隐私说明、`README` 的隐私小节、首次启动的告知、以及「默认关闭、显式启用」的默认值。

**结论**：除非明确要做「联网看书」这个产品方向，否则长期搁置。
README 的 FAQ 措辞保持「暂不支持，短期也不打算做」，不要写成「后续计划」，
免得用户等一个不会来的版本。

## 明确不做

| 项 | 原因 |
|---|---|
| Intel / universal binary | 没有机器做真机验证；盲出包比「明确不支持」更糟 |
| Apple 公证 / 签名证书 | 依赖开发者账号与凭据，属于发布流程外部条件 |
| 自动更新 | README 的卖点之一是「没有自动更新」，改起来要重新想隐私叙事 |
| MOBI | 原版也只是勉强支持，投入产出比太差 |
| 云同步 | 与离线承诺冲突，且便携模式 + 手动搬存档已经够用 |
| 无边框窗口（`styleMask = .borderless`） | 沉浸模式（`⇧⌘B`）已经收掉顶栏和底部状态栏，「只剩正文」的需求已满足；真无边框只多出「直角、没有标题栏区域」，却要另外处理 `⌘W`、窗口尺寸记忆（`saveWindowFrame` 靠 `.titled` 早退会静默失效）、与沉浸模式 / 全屏互斥，收益不抵风险 |
| 盖住别人的原生全屏 | 跨 Space 覆盖是系统没承诺的灰区，升级易坏；本需求只到「最大化不挡」 |
