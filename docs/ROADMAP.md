# Reader for macOS · 路线图

这份文件回答一个问题：**接下来做什么，以及明确不做什么。**
用户视角的功能说明见 [README](../README.md)，实现细节与踩坑记录见 [开发笔记](DEVELOPMENT.md)。

排期原则：**先把「读一本书」这件事补完整，再谈换格式和联网。**
所以顺序是「全文搜索 → 窗口置顶 → 排版能力补齐 → 发版 → EPUB →（大概率不做）在线书源」，
而不是按原版功能表从上往下抄。

工程约束（每个决策都受它约束）：

| 约束 | 后果 |
|---|---|
| 零第三方依赖 | 不做需要引入库的功能（例如现成的 ZIP / HTML 库） |
| 只出 arm64 | 不承诺 Intel 支持，除非有机器可以真机验证 |
| `.cache.dat` 与 Windows 版字段互通 | 不新增「必须写进存档才能工作」的核心状态；Mac 专属偏好一律走 `macos_*` 自定义键 |
| 位置一律是 `FormatText` 之后的 UTF-16 码元下标 | 任何新功能都必须用字符偏移，不能引入「页码 / 百分比」当坐标 |
| 完全离线 | 联网功能需要先改产品承诺，见 M7 |

## M1 全文搜索（已完成）

**目标**：`⌘F` 一次扫完整本书，列出每一处的章节与上下文；回车 / `⌘G` 往下、
`⇧⌘G` 往回；当前页高亮；关面板清高亮。

**关键决策**

- 匹配交给 `NSString.range(of:options:range:)`：返回值天然是 UTF-16 下标，
  和进度 / 书签 / 章节锚点是同一套坐标。自己折叠大小写会改变长度，
  下标就不是原文偏移了。
- 命中**非重叠**（`aaaa` 查 `aa` = 2 处），单次最多收 2000 处（`truncated` 提示）。
- **搜索不跳页**：结果只列出来（顺手选中离阅读位置最近的一处），跳转必须是用户的主动动作 ——
  双击结果行、回车、点「跳转」，或 `⌘G` / `⇧⌘G`。打字时结果每 250ms 换一批，
  自动跳页会一边打字一边把人甩走。
- **关闭 = 本次查找结束**：关掉面板会清空输入框、结果和高亮；下次 `⌘F` 是干净的一次查找，
  不会带着上次的词，也不会跳回上次的位置。
- 输入防抖 250ms + 后台队列 + generation 丢弃过期结果，长篇打字不卡。
- 高亮只画「当前页 + 平滑滚动的下一页」的交集，翻页 / 换字号后自动重算。
- `⌘F` 归查找，全屏改为 `⌃⌘F`（系统标准「进入全屏幕」）。

**验收**：`./verify.sh` 里的 `4.9/5 全文搜索自检` 全绿；单测含偏移、大小写、
非重叠、上限、环绕、片段裁剪、设置往返；自检覆盖「搜索不跳页 / 单击不跳 / 关闭清空输入框 /
重新打开是空白查找」；离屏渲染 `--render-find` 与 `--render-page … --find 之` 人工确认高亮。

**实测**（638 万码元长篇，单测里已断言）：缓存构建 0.7ms（**不能**退回
`String(decoding:)`，那是 617ms）、命中密集 32ms、全书零命中扫描 171ms，
全部在 300ms 预算内。

## M2 窗口置顶（已完成）

**目标**：勾上设置后，主窗口浮在其它应用的普通窗口 / **最大化窗口**之上；
点别的应用也不会被挡在后面，方便一边在别的软件里干活、一边看着书。

**做法（最小、稳定的一级）**

- `window.level = .floating`（关掉时回到 `.normal`），在 `applyWindowChrome()` 里统一应用。
- `window.hidesOnDeactivate = false`：失焦不隐藏。NSWindow 默认就是 false，
  显式写出来是防止以后为了「不抢焦点」把主窗口改成 `NSPanel` 时悄悄变成默认 true。
- **只置顶主窗口**：辅助窗口（设置 / 书架 / 书签 / 查找）保持普通 level，不跟着浮在
  别的应用上面。但 level 是系统级绝对排序，主窗口 floating 时辅助窗口会被书盖住，
  所以辅助窗口可见期间主窗口临时降回 normal，关掉后（主窗口重新成为 key）自动恢复。
- 开关联动（同一个 `keepOnTop` 设置，任一处切换其它处立刻同步）：
  **菜单「视图 → 窗口置顶」`⌃⌘T`**、**右上角菜单栏图标的菜单**、**设置 → 窗口 → 置顶**。
  托盘菜单打开时按 `menuNeedsUpdate` 重读状态，主菜单项由 `syncKeepOnTopMenuState()` 统一刷新。
- 存自定义键 `macos_always_on_top`（Windows 版忽略）。

**明确不做**

- 盖住别人的**原生全屏**（绿色按钮）：那是独立 Space，要 `.canJoinAllSpaces` +
  `.fullScreenAuxiliary` + 更高 level，属于系统没承诺的灰区。本需求只要「最大化不挡」，
  floating 就够，而且稳定。
- 「点窗口不抢焦点」：用户明确说焦点丢了没关系 —— 滚轮悬停在阅读器上照样能翻，
  鼠标事件是按窗口命中派发的，不需要窗口是 key。

**验收**：`--always-on-top-selftest` 全绿（默认 normal、开启后 floating、失焦不隐藏、
辅助窗口保持 normal 且主窗口临时降级、关掉辅助窗口后恢复、三处开关联动、写盘后重新加载仍生效）；
单测覆盖设置往返与 level 数值关系；人工：勾上后切到别的应用，
窗口仍在最上面。

## M3 章节标题独立字体 / 颜色

**为什么**：`.cache.dat` 里 `use_same_font` / `font_title` / `font_color_title`
三个字段已经能读写，但渲染层只有一个字体 —— 从 Windows 版搬过来的用户会发现
「设置还在、效果没了」。

**做法**

1. `ReaderSettings` 增加 `useSameFont`（header `use_same_font`，原版默认 1）、
   `titleFontName` / `titlePointSize`（header `font_title` 的 LOGFONT，
   换算与正文字体相同）；`titleColorRef` 已有。
2. `ReadingView` 从单个 `metrics` 变成「正文 / 标题」两套 `TextMetrics`；
   `LineBox` 增加 `style`（`.body` / `.title`）；`layout(from:)` 里标题行用标题度量
   算宽度和行高；`drawLines` / `drawChar` 按行取字体与颜色。
3. 设置界面「显示」页加「章节标题」分节（checkbox + 字体 + 颜色），
   复用现有 `syncFromSettings` 刷新套路。

**兼容性红线**：默认值仍是「同字体同色」，所以 `samples/golden-pages.tsv`
不该变；用户开启后每页行数可能变化，但进度 / 书签是字符偏移，不受影响。

**验收**：字段 round-trip 单测；默认设置下 `--dump-pages` 与基准快照逐行一致；
开启后标题行高与正文不同（单测断言）；离屏渲染一张开启前后的对比图。

## M4 背景图片 + 无边框窗口

**背景图片**（原版 `bg_image.enable / mode / file_name`）

- `mode` 语义照原版 `DisplaySet.cpp`：**0 = 拉伸、1 = 平铺、2 = 平铺翻转**。
- 绘制顺序：纯色底 → 背景图 → 正文；窗口 `alpha < 255` 时图跟着淡，
  但**文字始终不透明**（既有原则）。
- 文件不存在时回落纯色并在设置页提示，不弹窗、不崩溃。

**无边框窗口**

- 新增自定义键 `macos_borderless`（不动 Win32 的 `style` / `exstyle` 语义），
  `styleMask = [.borderless, .resizable]` + 保留 `minSize`。
- 必须处理的副作用：关闭按钮消失（留 `⌘W` 与菜单项）、
  `WindowDragStrip` 拖动条成为唯一拖动入口、与沉浸模式的
  `.fullSizeContentView` / 标题栏隐藏互斥、全屏切换后要还原。

**验收**：两个字段 round-trip 单测；无边框模式下窗口仍能拖动、能用 `⌘W` 关闭
（沿用 `--close-selftest` 的思路）；背景图缺失时渲染不崩。

## M5 0.2.0 发版

M1–M4 一起出包。步骤严格照 [开发笔记「发版」](DEVELOPMENT.md#发版release)：

1. `Resources/Info.plist`：`0.1.1 → 0.2.0`、`CFBundleVersion 2 → 3`
   （README 里的下载链接、文末版本号、Release 说明同步）。
2. `./verify.sh` 全绿。
3. `ditto -c -k --sequesterRsrc --keepParent`（**不能用 `zip -r`**，会丢扩展属性、
   签名失效）；`shasum -a 256`；解压后 `codesign --verify --deep --strict`。
4. 打 `v0.2.0` tag 推送 → 网页上传 zip + SHA256SUMS → 用 README 里的永久链接
   下载回来核对 SHA256。

Release 说明里必须写清楚两件事：
- `⌘F` 现在是查找，全屏改成了 `⌃⌘F`（老用户会按错一次）；
- 仍未公证，首次打开要「右键 → 打开」。

## M6 EPUB（押后）

**为什么押后**：不是不想做，是它需要一次结构性重构，而不是加一个解析器。

**前置条件**

1. 把 `TextBook` 抽成 `Book` 协议（`units` / `chapters` / `titleLength` / 书名 /
   路径），`ReadingView`、书架、`.cache.dat` 都面向协议。
2. 一个零依赖的 ZIP 读取方案。先做**原型**：用 `Process` 调系统自带的
   `ditto -x -k` 解到临时目录，读 `META-INF/container.xml` → OPF → spine。
   原型验证「值不值得」之后，再决定要不要用 libz 自己写 inflate。
3. 文本规范化要单独一套：不能复用 `FormatText` —— 那套规则是为 **Windows 存档
   偏移兼容** 服务的，硬套到 EPUB 上只会把排版弄坏。
4. 一个 spine 条目 = 一章（合并 HTMLBlock 文本）；图片 / 样式 / 注音先忽略，
   番外与目录页按章节规则处理。

**验收**：打开一本公开版权的 EPUB 能读到正文、章节表正确、进度可记忆；
不引入任何第三方依赖；`.cache.dat` 结构不变。

## M7 在线书源（暂不做，需要产品决策）

**技术成本**：URLSession + HTML 解析 + 一套 XPath 子集（原版 `bs.json` 是 XPath 规则）
+ 书源规则界面 + 章节下载与缓存。零依赖前提下这是典型的「大工程」。

**产品冲突**：README 现在明确写着「完全离线：不联网、不上传、不统计」。
一旦加入书源，这个承诺就不成立了，必须同时改：
隐私说明、`README` 的隐私小节、首次启动的告知、以及「默认关闭、显式启用」的默认值。

**结论**：除非明确要做「联网看书」这个产品方向，否则长期搁置。
README 的 FAQ 措辞保持「暂不支持，短期也不打算做」，不要写成「后续计划」，
免得用户等一个不会来的版本。

## 明确不做

| 项 | 原因 |
|---|---|
| Intel / universal binary | 没有机器做真机验证；盲出包比「明确不支持」更糟 |
| Apple 公证 / 签名证书 | 依赖开发者账号与凭据，属于发布流程外部条件 |
| 自动更新 | README 的卖点之一是「没有自动更新」，改起来要重新想隐私叙事 |
| MOBI | 原版也只是勉强支持，投入产出比太差 |
| 云同步 | 与离线承诺冲突，且便携模式 + 手动搬存档已经够用 |
| 盖住别人的原生全屏 | 跨 Space 覆盖是系统没承诺的灰区，升级易坏；本需求只到「最大化不挡」 |

---

## 怎么更新这份路线图

- 做完一个里程碑：把「状态」改成 ✅，并补一行「验收」里实际跑过的命令。
- 新想法先问三个问题：伤不伤害「离线」承诺？要不要改存档格式？
  是不是必须在没有第三方依赖的前提下做？三个都能过，再加进表里。
- 发版之后回填版本号，避免路线图和 README 里的版本对不上。
